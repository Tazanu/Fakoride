BUILD STACK What we build it with, and what we deliberately don't Chosen for two constraints that outrank everything else: it must run on a cheap Android over 3G, and it must not bill in dollars per trip while earning 250 FCFA.
LayerChoiceWhy this oneNot this
Rider & driver apps React Native + Expo (EAS) One TypeScript codebase for both apps, on the React you already write daily. EAS ships signed APKs and over-the-air updates that land without a Play Store round trip. Flutter — a second language to learn for no gain here
Maps MapLibre GL + OpenStreetMap Open tiles, vector rendering, offline-capable style. Buea's OSM coverage is workable and anything missing we add ourselves. Google Maps SDK — billed in USD per load
Routing & ETA OSRM on the Cameroon extract Self-hosted on one small box. Unlimited route calls at a fixed monthly cost, which is the only way per-trip routing survives at this fare. Google Directions API — cost scales with trips
Places Our own Fako gazetteer A few hundred hand-seeded landmarks and zone polygons in PostGIS. Nobody navigates Buea by street name, and no geocoder knows Malingo Junction better than we will. Any third-party geocoder as the primary
API Node + Express + Prisma, TypeScript The exact stack running StudyHub. Day-one productivity matters more than novelty for a two-month build. NestJS, Go — new idioms, same result
Database PostgreSQL (Neon) + PostGIS Zone polygons, point-in-polygon fare lookup and the trip ledger in one place. Branching databases make migrations safe to rehearse. MongoDB — no geometry, no ledger guarantees
Dispatch & realtime Socket.IO + Redis (Upstash) Driver positions and the 12-second offer queue live in Redis; sockets push offers and trip state. Reconnect logic is the hard part, not the transport. Polling — burns the driver's data bundle
Payments Fapshi, CamPay as fallback MTN MoMo and Orange Money through one API, with sandboxes. Fapshi is Cameroonian; CamPay's flat 2% is the benchmark to hold them to. Stripe, PayPal — irrelevant to this market
OTP & alerts Local SMS aggregator Phone-number login is the only login that works here. Price per SMS against local providers before committing — it is a recurring cost per signup. Twilio — international rates into Cameroon
Notifications FCM via Expo push Free, and it wakes the driver app when a ride offer arrives with the screen off. —
Ops console React + Vite on Vercel Driver verification queue, live trip board, fare-table editor, complaints. Same frontend stack as StudyHub, so it costs days not weeks. An admin framework — we need three screens
Hosting Render · Neon · Upstash · R2 The deployment shape you already run, plus Cloudflare R2 for driver documents — CNI photos and licence scans, which need storage that is cheap and access-controlled. Self-managed VPS for everything
Watching it Sentry + PostHog One crash on a driver's phone mid-trip costs a driver. Session data also answers the only question that matters early: where people drop out of booking. Nothing — flying blind on a two-sided app
SEQUENCE
NEXT · 2 WEEKS Field work

Count trips, interview 30 drivers and 50 students, walk the zone table, check the S10 paperwork. No code.

WEEKS 3–5 Spine

Schema, gazetteer, zone fare table, auth by phone, driver onboarding and the ops console. Dispatch as an API before it is a screen.

WEEKS 6–8 Driver app

Online toggle, offers, PIN, trip lifecycle, earnings. Tested on real bikes on the real corridor before riders exist.

WEEKS 9–10 Rider app

Book, track, pay, rate, share trip, SOS. Cash first; MoMo behind it.

WEEK 11+ One corridor

Mile 17 to Molyko only, 40–60 signed drivers, free for everyone. Widen only when the wait is under five minutes.
